## 这个产品的定位

心履的 Android 客户端：记心情、看日历与徽章、AI 树洞、推荐内容。
数据通过**两个服务端**同步 —— 心履自己的服务端（`xin-lv.com`）管心情记录，
phix（`phix.ing`）管统一账号与跨站免密登录、以及应用内更新检查。

## 工程约定（请遵守）

- **注释和提交信息用中文**，并且写**为什么**。
- **网络与耗时操作一律走 `util/Bg.java`**，绝不在主线程上做 I/O。
- **异步回调里先判断 Fragment/Activity 还活着**（`isAdded()`、
  `isFinishing()`、`isDestroyed()`）再碰视图 —— 这是安卓最常见的崩溃来源。
- **不要在界面上展示技术细节**：用户明确要求过客户端不给用户看服务器地址、密钥、
  同步游标这些内部信息。作者信息、版本号、官网链接是要展示的。
- 更新检查必须**三态分明**：已是最新 / 发现新版本 / **检查失败**；
  **"检查失败"绝不能显示成"已是最新版本"**。
- 打开外链/邮件用 intent 且**包 try/catch**，没有能处理的应用时只提示、不崩。
- 长轮询**只在前台跑**（`onStart` 起、`onStop` 停）—— 这是刻意设计，别"顺手"改成后台常驻。

  ```powershell

  .\gradlew.bat :app:testDebugUnitTest --offline   # 当前 9 个测试，0 失败
  ```

- 新逻辑要带测试，照 `WatchDecisionTest` / `UpdateReportTest` 的风格写
  （纯逻辑、可注入、不碰网络）。
- **本机没有模拟器和真机，界面没法自动验证** —— 如果你没在真机上看过，
  就**如实说"没验证界面"**，不要含糊成"已测试"。
- **不要用"我觉得应该没问题"结题**。跑过、看过、贴出证据再结题。

## 发版流程（需要发版时）

1. 改版本号：`app/build.gradle` 的 `versionName` **和 `versionCode` 都要加**
   （只加 `versionName` 覆盖安装会失败）。
2. `.\gradlew.bat :app:assembleRelease` → `app\build\outputs\apk\release\app-release.apk`。
   签名配置在 `keystore.properties`（**不进版本控制**，换机器要单独拷）。
3. 产物交给统一发布流程，**不要自己直接传服务器**。
4. 推送：`git push origin main`。

## 你要交付什么

每个任务结束时，报告里要有：改了哪些文件、**为什么这么改**、跑了什么命令、
**实际结果是什么**（测试数、失败数、release 包能不能出、
界面验证到什么程度——没验证就直说）、以及**你没验证到的部分**。
